# ТЗ на дизайн «Автобанк» (портал)

Основание: docs/design/2026-11-24-design-review.md (27/40, Acceptable). Режим поверхностей: ядро — **Operate**, /login и /start — **Persuade/Onboard**. Скиллы-исполнители: impeccable (harden/polish/layout/typeset/clarify/adapt), ux-copy, web-design-guidelines (финальный аудит), ui-ux-pro-max (подбор палитр/пар при необходимости), hallmark — только по явному вызову для новых страниц (лендинг).

## 1. Цели и принципы
1. **Одна кожа продукта**: рабочая область, вход, онбординг и кабинет выглядят как одно приложение.
2. **Правда вместо оптимизма**: отрицательные остатки и перерасходы сигнализируются цветом и текстом, не прячутся в «праздничные» плашки.
3. **Совместная книга = защита работы**: конфликт ревизий не уничтожает правки; удаления обратимы или подтверждены.
4. **Гараж-мобильность**: основной поток (очередь → карточка → расход/продажа/задача) работает одной рукой на 390px.
5. **Сдержанность Operate**: самобытность — в точных деталях (тёплая бумага, зелёный rail, лаймовый highlight, госномер, марочные значки), не в лендинговых приёмах.

## 2. Дизайн-система (итерация 1, блокер поддержки)
- **Один слой токенов** в workspace.css :root; globals.css оставляет только базовые reset/формы/диалоги и auth-компоненты, переведённые на токены. Удалить :root №1 (Inter) и синюю тему :root №2 (globals.css:479-547) и мёртвые правила (.metric/.tabs/.badge-* старой темы), если не используются workbench-классами.
- **Цвета** (формализовать текущую тёплую палитру): --page #f3f1e9; --surface #fffdf7; --rail #172d25; --ink #192c26; --muted #53635a; --line #dedfd2; --brand #1d5644; --focus #15654d; --good #246047; --bad #a02d3b; --highlight #dcefaa; добавить --warn #7b501b и --surface-raised (для карточек вместо #fff). Все литералы цветов в компонентах заменить токенами (кроме chart-серий — вынести в --chart-*).
- **Типографика**: Manrope Variable единственный; шкала 12 / 14 / 16 / 20 / 28 / 40px (rem: .75/.875/1/1.25/1.75/2.5); веса 400/600/700/800; display-h1 Operate-экранов ≤28px (clamp(1.5rem,2.2vw,1.75rem)); tabular-nums для всех сумм и дат; мелкие подписи ≥12px.
- **Радиусы**: 6 (контролы) / 10 (карточки) / 14 (модалки/тур); **отступы**: 4/8/12/16/24/32/44; **motion**: --control-motion 155ms ease-out, --panel-motion 240ms cubic-bezier(.18,.76,.26,1); только конкретные свойства; prefers-reduced-motion обнуляет.
- **Контролы**: primary/secondary/icon/segment/link — пять видов, высоты 44 (desktop) / 44 (touch); сегменты и поиск/сортировка ≥40px на desktop и ≥44 на touch-брейкпоинте.
- Критерий приёмки: grep по app/*.css не находит второго :root и font-family кроме Manrope-стека; размеры шрифта только из шкалы; радиусы только 6/10/14/50%.

## 3. Доверие и деньги (итерация 1, P1)
- **Отрицательная касса**: при available < 0 плашка получает класс negative (фон --bad-soft, текст --bad), бейдж «Перерасход», строка «Списания превышают поступления на X ₽» и кнопка «Разобрать в кассе». То же в hero Кассы. Тест: рендер при отрицательном остатке (браузерный чек + unit на класс).
- **Конфликт ревизий (409)**: диалог НЕ закрывается; ledger перезагружается фоном; draft формы сохраняется в состоянии; баннер в диалоге «Книгу изменил другой участник. Сверьте изменения и сохраните снова»; поля без конфликта авто-мержатся; конфликтные подсвечены с «было/стало» из аудита. Тост конфликта — со ссылкой «Показать изменения». Тест: два клиента, правка разных полей → мерж; одного поля → подсветка, draft цел.
- **Удаления**: confirm для задачи и участника книги (текст последствий в стиле проекта); тост с «Вернуть» (undo последнего удаления) для авто/расхода/задачи/движения; участник — undo не нужен, confirm достаточно.
- **Тосты**: очередь (не затирать), пауза по hover/focus, действие («Вернуть», «Показать»), время 6 с для сообщений с действием.

## 4. Консистентность и когнитивная нагрузка (итерация 2, P2)
- Карточка авто: вкладки **История / Деньги / Работы и фото / Задачи** + «Ещё» (Запчасти, Правки); убрать дубль-свёртку «Правки участников» внутри Истории; «Расчёты» реестра оставить (режим таблицы), в карточке — «Деньги».
- Даты: единый dateLabel везде; задачи — «до 24 нояб» вместо ISO; лента — «24 нояб 2026, 21:07» (год обязателен на стыке лет).
- Лента книги: 8 фильтров сгруппировать в 2 ряда-чипса «Сущности: Авто/Расходы/Задачи/Запчасти/Партнёры» и «Деньги: Касса/Выплаты», «Все» — сброс.
- Тулбар реестра: primary-ряд (поиск, сортировка, Обзор/Расчёты), вторичное (пин, Все/В работе) — в один ряд чипсов под поиском на ≤900px.
- Аналитика при пустом годе: вместо стены нулей — одно пустое состояние «Продаж и расходов в 2026 пока нет» + кнопка «Добавить авто»; band-карточки скрывать до первой продажи.
- /account: UA → «Chrome на Windows» (парсер строки, fallback «Браузер»), дев-подсказка кода только при SMS_DEV_MODE=1; «Удалить» участника — confirm.
- /login: редирект на / при активной сессии; «Сброс пароля» — текстовая ссылка под формой, не равноправный таб.

## 5. Мобильность и доступность (итерация 2, P2)
- Nav ≤900px: 5 равных колонок (или горизонтальная скролл-лента с snap); рассмотреть нижний бар для ≤650px (решение по итогам браузерного прогона-thumb-зоны).
- Тач-таргеты: чекбокс задачи и корзина ≥44px (визуальный чекбокс 22px внутри 44px-хитбокса); сегменты/поиск/сортировка/пин ≥44px на touch; подписи этапов ≥12px.
- Семантика вкладок: единый паттерн role=tablist/tab/tabpanel + aria-controls для карточки, реестра, кассы, /login; стрелки ←→ переключают, Home/End — края.
- Тур: focus trap (Tab циклится внутри), возврат фокуса на элемент-инициатор; кнопка «Показать обучение» в кабинете/помощи (повторный вызов).
- Диалоги: sticky-футер с действиями (globals.css .dialog-inner → flex column, footer position sticky bottom 0, фон --surface); «Сохранить» всегда видим.
- Финальный прогон web-design-guidelines по app/*.tsx: 0 находок severity выше minor.

## 6. Эффективность (итерация 3, P2/P3)
- Хоткеи: `/` фокус поиска, `n` добавить авто (на главной), `Esc` уже есть; подсказка хоткеев в тултипе поиска.
- «+ Расход» прямо из строки реестра (иконка в ячейке действий) и из очереди шагов.
- Bulk: множественный выбор машин → «Отметить этап» (только этап, без денег) — опционально, по решению владельца.
- Контекстные тултипы: «доли прибыли vs взносы», «банк vs касса», «Без распределения» (ux-copy тексты).

## 7. Что НЕ трогаем
Деньги/копейки/as-of/инварианты parseLedger, API и коды 409/422 (кроме UX-обработки конфликта на клиенте), аудит-инварианты, роли/доступ, CSRF, rate-limit. Любое изменение клиентской модели — через ledgerClientVersion и точечные 409-проверки.

## 8. Приёмка и проверка
- `npm run check` (tsc + все тесты) и `npm run build` зелёные; новые тесты: конфликт-draft/мерж, negative-класс кассы, undo-тост, confirm задачи/участника, dateLabel задач.
- Браузерный прогон: desktop 1280×800 и 390×844 (эмуляция), сценарии: очередь→карточка→задача (промах-тест таргетов), продажа с превью, конфликт двух вкладок, удаление+undo, пустая аналитика, login/logout/account.
- Контраст всех текстовых пар ≥4.5:1 (computed-проверка), таргеты ≥44px на touch, один шрифт, шкала размеров/радиусов соблюдена (grep-линты).
- Повторный impeccable critique: цель ≥32/40 (Good); детектор 0 warning после удаления legacy-слоя.
- Каждый этап — отдельная ветка/коммит в стиле проекта, ревью диффа для денег/хранения/доступа обязательно.

## 9. Порядок работ
1. Итерация 1 «Система и доверие»: токены/одна кожа + negative-касса + конфликт-draft + confirm/undo + тосты. (P1, ~1 коммит-серия)
2. Итерация 2 «Ясность и мобильность»: нейминг/даты/группировки + пустые состояния + nav/таргеты/семантика/тур/sticky-футер + login/account. (P2)
3. Итерация 3 «Эффективность»: хоткеи, «+расход» из строки, тултипы; финальный аудит и повторный critique. (P2/P3)
