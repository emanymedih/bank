# Фаза 3 — UX-пакет (план, 24.11)

Ветка `feature/portal-foundation`. TDD: падающие тесты → реализация → `npm run check` + `npm run build` → браузер → ревью.

## Объём (из дизайн-дока)
1. **Общий таск-трекер по машине**: `car.tasks [{id,title,due?,done,author?,createdAt}]` — общие на книгу; вкладка «Задачи» в карточке; ближайшая открытая задача питает очередь «Следующие шаги» (совместимость с `nextAction`).
2. **Ссылка на объявление**: `car.listingUrl` (http/https, домен не жёсткий); поле в форме авто + кнопка «Объявление» в карточке.
3. **Совместимость**: `ledgerClientVersion` 4→5, точечный 409 (`version < 5 && есть tasks/listingUrl`).
4. **Аудит**: сущности `task` и `part`, поле `listingUrl`; фильтры ленты «Задачи»/«Запчасти».
5. **Предпросмотр «что изменится»**: в форме продажи (касса ±, прибыль по партнёрам) и выплаты (остаток прибыли, касса ±).
6. **Итоги этапов**: «вложено» в шапках этапов StageBoard.
7. **Закреплённые фильтры**: реестр — сохранить/сбросить фильтр+сортировку+поиск в localStorage на книгу.
8. **Единая лента авто**: аудит-правки свёрнутым блоком «Правки участников» в ленте карточки (работы+расходы+этапы уже там).
9. **Обучение при первом входе**: тур из 4 шагов (книга/роли → касса → авто по ГРЗ → лента/правки), один раз на пользователя, пропускаемый; тексты через ux-copy, оформление через impeccable.

## Инварианты
- Уникальность id задач в машине; заголовок 1..120; срок — валидная дата; ссылка — http/https.
- Деньги не трогаем: задачи и ссылка не влияют на расчёты.
- Все прежние тесты зелёные; D1-лимит параметров соблюдён (аудит чанками).

## Проверка
- tests/phase3.test.mjs (ядро + API), полный `npm run check`, сборка.
- Браузер: задачи (добавить/выполнить/удалить), ссылка, предпросмотр продажи/выплаты, итоги этапов, закрепление фильтра, тур.
- Независимое ревью всех фич (subagent) + UX/UI-прогон по скиллам.
