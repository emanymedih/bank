# Фаза 2 — аудит и лента событий (план)

Ветка: `feature/portal-foundation` (продолжение). Спецификация: `../specs/2026-11-24-portal-design.md`.

## Цель
Любое изменение общей книги имеет автора и «было/стало», находится за два клика:
журнал книги («Лента» в рабочей области) и журнал правок в карточке авто.

## Хранение
- Миграция `0002_audit_events.sql`: append-only таблица `audit_events`
  (seq autoincrement, book_id, user_id, user_name — снимок имени, at, revision,
  entity: car/expense/cash/partner/payout, entity_id, entity_name, car_id?,
  action: create/update/delete, field?, before?, after? — JSON-текст).
- Индексы: (book_id, seq) и (book_id, car_id, seq).
- Хранятся последние 1000 событий книги (обрезка после записи).
- ПДн: только user_id + снимок имени; телефон не хранится.

## Серверный diff
- Чистый модуль `lib/ledger-audit.ts`: `diffLedgers(before, after) → AuditRow[]`.
- Сущности: партнёры (имя), движения кассы (название/дата/сумма/направление/распределение),
  авто (ключевые поля + доли), расходы авто, выплаты по долям.
- create/delete — одна строка со снимком; update — строка на каждое изменённое поле.
- Деньги — целые копейки, без float; undefined ≡ null.

## Запись и доступ
- PUT /api/ledger после успешного сохранения пишет diff с автором (requireBook).
  Ошибка аудита не ломает сохранение (лог).
- GET /api/books/events?carId=&entity=&limit=&cursor= — чтение для всех ролей книги;
  чужая книга → 404/403; пагинация по seq (cursor), порядок новые→старые.

## UI
- Раздел «Лента» в сайдбаре: группировка по сессии правки (автор + время),
  строки «сущность · действие · поле: было → стало», деньги в рублях.
- Фильтры: все / касса / авто / расходы / выплаты / партнёры; «Показать ещё».
- Бейдж новых событий на «Ленте» (localStorage lastSeenSeq по книге).
- В карточке авто вкладка «Правки» — события по carId.
